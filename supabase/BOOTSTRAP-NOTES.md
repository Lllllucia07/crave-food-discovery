# Hosted project bootstrap

Project: `nbkomdruopguehnfymib` (`crave`), organization `Crave_app`, Free Plan, Ohio.

Initialized through the authenticated Supabase SQL Editor on 2026-11-23 after confirming the public schema was empty. The initial schema, four-argument radius-aware ranking function, explicit table grants, foreign-key indexes and 500-call shared monthly Google budget were applied transactionally. All eight tables have RLS enabled. Tables/functions were checked via SQL; the budget accepted 500 calls and rejected the next call inside a transaction that was rolled back.

`fetch-places` and `recommend` were deployed through the Dashboard from standalone bundles matching the local source. The legacy gateway JWT check is disabled because each function validates the actual user JWT through Supabase Auth `getUser`; both unauthenticated endpoints return 401. No Google request can be made before the API key is configured. The global Google budget counts each attempted outbound request conservatively, including individual saved-place refreshes, and stops the app at 500 requests per UTC calendar month. It does not cover other projects or uses of the same Google billing account.

Anonymous sign-ins were enabled with user approval. A smoke test created two anonymous sessions and verified own-row access, cross-user isolation, rejection of direct client quota RPC calls, authenticated recommendation RPC success, and a 503 when Google is unconfigured. Test profile rows were removed and both sessions signed out. No Google requests were made. Google Places is now configured in encrypted Edge Secrets. The active key belongs to the Google onboarding project `project-16109ca4-ec2c-4743-a5a` (My First Project), and is named `Crave Backend Places` with only Places API (New) enabled in its API restriction. The separate unused project `crave-food-discovery-515622` was also created during setup; no deletion or billing reassignment was performed. A live API smoke test returned 20 real restaurants, five ranked recommendations, a rating/review count and five attributed Google reviews. Only two outbound Google requests were used for that smoke test. Public Supabase URL/publishable key are saved in the ignored local `.env.local`. Never commit privileged credentials. The frontend uses the ignored local public configuration to build the live Site; Google and admin secrets are never bundled.

SQL Editor execution does not create CLI migration history. Do not blindly run `supabase db push` against this initialized project. First inspect the remote schema, reconcile it with the three local migration files and then baseline/repair history using the current CLI's supported workflow.
